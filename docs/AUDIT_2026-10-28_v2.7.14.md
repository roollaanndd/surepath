## Temuan keamanan

### Yang sudah kuat (terverifikasi di kode)

Verifikasi JWT terpusat di dispatcher + gerbang kepercayaan; idempotensi
webhook Xendit dengan atomic claim `.neq('status','PAID')` + verifikasi
nominal vs `total_premium`; OTP: gerbang anon-key, rate limit 3/10 menit per
HP + 10/jam per IP, lockout 5 percobaan, CSPRNG; `notify-admin` fail-closed +
HTML-escape; CORS gateway allowlist; `sp_activity_log` tanpa nilai sensitif;
audit log immutable; deny-all RLS + REVOKE EXECUTE pada helper; nol rahasia
di repo (`VITE_ADMIN_KEY` dev-only).

### P1 (diurutkan; perbaiki sekelompok)

**P1-A — Injeksi filter PostgREST di 9 lokasi.**
`supabase/functions/data-gateway/actions/` → `claims.ts:138`,
`mitraAccounts.ts:168`, `orders.ts:354`, `orders.ts:428`, `orders.ts:509`,
`users.ts:200`, `users.ts:256`, `serviceTools.ts:345`, `tools.ts:332`.
Input pengguna (nomor order / kode ref / coverage) diinterpolasi langsung ke
tata bahasa filter `.or()`; koma dapat menyuntik kondisi `eq` tambahan, dan
gateway berjalan dengan **service_role** (melewati RLS) → risiko kecocokan
lintas-tenant pada lookup by-ID.
*Fix: validasi format ketat (regex nomor order/policy/kode) SEBELUM
interpolasi — pola sama dengan FIX v2.6.18. Tambahkan test regresi
parametrik di CI.*

**P1-B — Endpoint `server.ts` tanpa autentikasi.**
`/api/ai-audit-log`, `/api/ai-cache-stats` (baca data internal),
`/api/ai-admin/run` (POST memicu aksi bisnis), `/api/aistudio-test` (tanpa
rate limit — biaya API Gemini dapat disalahgunakan). Berlaku saat build
di-deploy sebagai server mandiri (`npm start`, port 3000, bind `0.0.0.0`).
*Fix: gerbang secret/admin-JWT pada /api/*; rate limit khusus aistudio-test.*

**P1-C — Konflik Permissions-Policy kamera (TERVERIFIKASI silang).**
`server.ts:45` memakai `camera=(self)` (komentarnya sendiri: capture dokumen
agen bergantung padanya), tetapi `vercel.json` (header Permissions-Policy)
memakai **`camera=()`** → **kamera diblokir di produksi Vercel**, padahal
self-host selalu berfungsi. Berkaitan dengan keluhan kamera/foto pada masalah
produksi (lihat PLAYBOOK Bagian 5).
*Fix: samakan ke `camera=(self)` di vercel.json.*

### P2

1. **xendit-webhook menelan kegagalan pra-claim** —
   `supabase/functions/xendit-webhook/index.ts:102-105`: error `payErr`
   dijawab `200`, padahal kegagalan sebelum row di-claim seharusnya `500`
   (agar Xendit retry) dan memicu notifikasi admin. *Fix: 500 + notify-admin.*
2. **Token compare tidak timing-safe** — webhook `!==` (dan `notify-admin`
   pada line 56). *Fix: `crypto.timingSafeEqual` dengan hash berpadding.*
3. **CSP longgar + allowance mati** — `vercel.json:8` & `server.ts:23`
   mengizinkan `'unsafe-inline' 'unsafe-eval'` + `esm.sh` /
   `prod.spline.design`, padahal `index.html` tidak memuat keduanya →
   permukaan XSS melebar tanpa manfaat. *Fix: hapus allowance tak terpakai;
   pertimbangkan nonce untuk inline script.*
4. **`verify-otp` tanpa rate limit per-IP** (brute force hanya bertumpu pada
   counter 5 percobaan per kode) + kode OTP tersimpan plaintext di
   `sp_otp_codes`. *Fix: pakai `sp_rate_limits` (`increment_rate_limit()`
   sudah tersedia) + hash kode.*

### P3 (ringkas)

- `/api/payments/create` + `/payment-simulation` di `server.ts` adalah
  simulator token palsu (`mok_…`) — pastikan tidak pernah terekspose di
  produksi (env guard).
- 28 warning ESLint; 11 di antaranya `react-hooks/exhaustive-deps` di portal
  agent/klien (`AgentClaims.tsx:302`, `AgentOrderStatus.tsx:232`,
  `B2BQuotes.tsx:205`, dll.) — pola `load()` tidak masuk deps → risiko data
  basi.
- 2 handler error gambar memakai `innerHTML` (`InsurerOrders.tsx:432`,
  `OperatorAgents.tsx:308`, `OperatorOrders.tsx:344`) — string statis,
  dinilai aman, namun polanya perlu penggantian ke atribut.
